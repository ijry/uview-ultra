## 对齐 uview-plus 3.8.129 ~ 3.8.137 到 uview-ultra（4.5.74）

基线：ultra 4.5.50 对齐的是 3.8.127 / 3.8.128（changelog 有明确记录），
所以从 3.8.129 起的 16 个提交逐个核对。

### 移植的（ultra 确实缺失）

- up-form：未配置 trigger 的规则视为任意触发（`[].concat(undefined)` 不含事件名导致规则永不生效）；
  toast 提示移入 validateField。.uvue 侧 trigger 逻辑本来就对，只补了 toast。
- up-form-item：新增 `resolvedBorderBottom`，未显式设置时跟随 up-form。
  判「显式设置」用的是 form-item 的 borderBottom 默认值 `''`（form 的是 `true`），
  不用 vnode.props（.uvue 拿不到）。
- up-input：watcher 早退分支补 firstChange 复位；doBlur 补 typeof 判断。
- up-sticky：`addUnit(stickyTop, 'px')`。ultra 的 `addUnit(value, unit)` 不传 unit 时
  走 `config.unit || 'px'`，且 unit==='rpx' 会 `value*2` —— 这就是 #1063 的二次换算。
  .uvue 版本来就是 `+ 'px'`，只需改 .vue。
- up-select：打开时先复位对齐再挂载；溢出判断改「触发区左缘 + 面板宽度」+ else 复位。
  .uvue 版结构不同（每次打开都 if/else 全赋值，不存在「永久贴右」），
  只补了一次面板自身宽度测量（面板 minWidth=触发区宽度，内容更宽时按触发区宽度算会漏判）。
- up-number-keyboard：去掉 `@touchstart.stop`（编译成 catchtouchstart 会吞掉同节点 tap），补 @touchcancel。
- up-cropper：新增 fileType（5 处硬编码 png → expFileType）；quality 改 parseFloat 夹 0~1；
  safeAreaInsets 兜底；操作栏 height = 50 + 安全区 + padding-bottom。
  用 `state.fileType`（初值 props.fileType）而非直接读 props，让 params.fileType 也能覆盖。
  .uvue 是完全不同的自绘面板实现，不适用。
- up-upload：新增 mediaType（props.js/.uts、upload.js/.uts、types.uts、d.ts、两套组件）；
  chooseMedia 去掉 `#ifdef MP-WEIXIN`，改 `typeof wx !== 'undefined' && typeof wx.chooseMedia === 'function'`
  （上游写的是裸 `if (wx.chooseMedia)`，H5 下 wx 未定义会 ReferenceError，这里加了 typeof 保护）。
- up-icon 字体插件：`app-icon-font.js` 原按 rootPath 拼死 `uni_modules/uview-ultra/...` 绝对路径，
  改 `endsWith('uview-ultra/components/up-icon/util.js')` 后缀匹配，覆盖 npm/pnpm。

### 判定为不适用（写进了 changelog 的「说明」段）

- children 时序守卫（#1065）：ultra 的 `children = ref([])` 在 setup 顶部初始化，
  不会有 options API 那种「watch 早于 created」的 undefined。**这是 ultra 相对 3.x 的结构性优势**。
- u-lottie（3.8.135 新组件）：三套渲染引擎，另立任务。

- `pnpm sync:demo` 补了 3 个缺失的 vapor-theme 示例页，示例页漂移 5 → 0。

## u-lottie 移植（4.5.75）

上游 3.8.135 新增的组件，上次判定「三套渲染引擎、另立任务」，本次完成。

### 架构：两条轨，不是三条

- `.vue` 侧（uni-app Vue3）：H5 / App-Vue 用 lottie-web 5.13.0 的 SVG 渲染器；
  微信小程序 / 鸿蒙用 lottie-miniprogram 1.0.12 + up-canvas。
  鸿蒙的 `harmony-canvas-adapter.js` 自包含、无 u- 前缀引用，可直接搬。
- `.uvue` 侧（uni-app x）：无 DOM，只能走 canvas。用 up-canvas 的
  `getRawContext()`（返回原生 `CanvasRenderingContext2D`）承载 lottie-miniprogram。

### 关键发现：uvue 能 import 压缩过的 lottie-miniprogram

`.uvue` 里 `import x from './libs/lottie-miniprogram.min.js'` **能编译通过**，
只报 `Use of eval ... strongly discouraged`。说明 uni-app x 对 `.js` 走普通 JS
处理，不是 UTS 严格解析。这打开了 uvue 侧复用 web 引擎的路子。

### 关键坑：lottie-miniprogram 在**模块加载期**就调 wx

源码里有 `var b = wx.getSystemInfoSync()`（模块顶层，不是函数内），
uni-app x 没有 wx 全局 → 直接 import 会在启动时 ReferenceError。

解法：生成一份注入 `var wx = {...}` 的副本 `libs/lottie-miniprogram.uvue.js`。
- 用 `var wx` 写在模块顶层，压缩代码里的自由变量 `wx` 会解析到这个局部 var，
  **比挂 globalThis 可靠**（UTS 产物里不保证有 globalThis）
- 原文件保持不动，供 `.vue` 侧（有小程序真 wx）使用
- 生成脚本 `libs/gen-uvue-variant.py` 留在仓库里，副本可重新生成

`setup(canvas)` 需要 canvas 节点（读 width/height、调 getContext('2d')），
uni-app x 没有节点对象，用 `UpLottieCanvasStub` class 包一层。

### 门禁需要放行第三方引擎

`verify-vue-build.mjs` 的 no-undef 扫描和模块加载冒烟会把 lottie 引擎算进来，
报 31 处未声明标识符（`OffscreenCanvas` / `wx` / `document` 等）。
已加 `THIRD_PARTY_ENGINE_DIRS` + `isThirdPartyEngine()` 跳过
`components/up-lottie/libs/`，两处扫描都加了过滤。

### 本机无法做 uvue 运行时验证（环境阻塞）

- MuMu 启动被沙箱拦：`PROGRAM BLOCKED BY SECURITY POLICY - sc.exe`，
  在黑名单里，无法绕过 → 模拟器起不来（adb 端口通但 package service 未就绪）
- 真机 `1569196572001LP` 在线且 `io.dcloud.uniappx` 在前台（dumpsys 确认），
  但 `screencap` 抓到的是另一个 app（MCode）的界面，截图不可信
- 结论：uvue 侧只做了编译级验证（109 页面全过），真机运行待补
