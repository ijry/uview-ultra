## 为 uview-ultra 的 uni-app Vue3 侧建了独立测试工程与编译门禁

**背景**：用户反馈「uview-ultra 在 uni-app vue3 模式下跑 bug 很多」，附了 8 条 bug 清单。

**根因定位**：`uview-plus4` 是 uni-app x 工程（`manifest.json` 有 `uni-app-x` 段、
`main.uts` 导入 `index.uts`），而 `uview-ultra` 的 `components/up-*/` 下是**双实现**——
`.uts/.uvue`（uni-app x，被 uview-plus4 编译）和 `.js/.vue`（uni-app Vue3，**没有任何工程编译**）。
所以 Vue3 那套（153 个 `.vue` + 260 个 `.js`）从来不过编译链，bug 只能靠用户反馈。

**产出**：新建同级工程 `D:/Repos/xyito/ultra-ui/uview-plus4-vue3`（**不在 uview-plus4 目录内**，
避免嵌套 uni-app 工程互相干扰）：

- `src/` 为 UNI_INPUT_DIR（uni CLI 默认值），`easycom` 指向 `up-*.vue`
- `src/uni_modules/uview-ultra` 是**目录联接**，指向 `uview-plus4/uni_modules/uview-ultra`，改一处两边生效
- `src/pages/index/index.vue` 用 `import.meta.glob('../../uni_modules/uview-ultra/components/up-*/*.vue', { eager: true })`
  全量拉进构建
- `scripts/verify-vue-build.mjs` 四段门禁：SFC 编译扫描 / babel no-undef / Node 模块加载冒烟 / 真实 `uni build`

**门禁一次跑出 7 处真问题、0 假报错**：
- `up-action-sheet.vue`、`up-text.vue`：`defineProps({ ...commonProps })` spread 局部变量
- `up-parse.vue`：条件编译导致的语法错误（`name: 'up-parse',` 后面接 `, components:`）
- `up-grid/props.js`：`crtProp is not defined`
- `up-calendar-strip/props.js`、`up-guide/props.js`：引用 `libs/config/props.js` 不存在的 `registerComponentProps`

**踩过的坑（已固化到 skill `uview-ultra-vue3-gate`）**：
1. `import.meta.glob` 用 `@/` 别名在 junction 下不展开，必须用相对路径
2. 解析源码前必须裁剪条件编译，且标记可能在行中间（`} else /* #endif */ if (...)`）
3. `spawnSync` 带 pipe 在本机必 `EBUSY`（杀软拦管道），要改成 `stdio: ['ignore', fd, fd]`
4. Rollup 不报未定义全局，`UpNoNetwork` 只能靠 babel no-undef 抓
5. Node ESM 不解析省略扩展名/目录导入，需挂 resolve 钩子
6. pnpm 要 `onlyBuiltDependencies: ["esbuild", ...]` 才能装上 esbuild 二进制

**未做**：那 8 条 bug 本体没修（用户本轮只要「搭工程 + 全量编译门禁」）。

### 最大的一类坑：`.uts` 抢 `.js`

uni-app 的 `resolve.extensions` 是 `['.uts', '.mjs', '.js', ...]`，**`.uts` 排第一，
非 uni-app x 构建也一样**（`@dcloudio/uni-cli-shared/dist/constants.js` 的 `COMMON_EXTENSIONS`）。
于是库里所有「同名 `.js`/`.uts` 并存 + 省略扩展名」的导入在 Vue3 下都解析到 `.uts`，
目录导入（`libs/i18n`）会解析到 `index.uts`，运行时直接 `UTSJSONObject is not defined`。
写脚本给 **154 + 14** 处补了显式 `.js`（`scripts/fix-vue-import-extensions.mjs`）。

### 示例页转换又补的规则

- 示例页里显式 `import ... from 'xxx.uts'` → 改成 `.js`；没有 `.js` 孪生的（`types/index.uts`）
  改成 `import type`（esbuild 会整条擦除）
- uvue 的 `ref.$callMethod('name', args)` → Vue3 的 `ref.name(args)`（48 处、19 个页面）
- `.config.uts` → `.config.ts`

### ⚠️ 本仓库是「混合行尾」，改文件千万别用会统一行尾的编辑器

`uview-plus4` 里 HEAD 存的是**混合行尾**——同一个文件里既有 CRLF 又有 LF
（例：`up-steps-item.vue` 349 行里 194 行 CRLF、155 行 LF）。
用 Edit 工具（或任何会把整份文件行尾统一掉的写法）改一个文件，git diff 会凭空多出几百行。

正确做法：**用字符串替换，除替换片段外一个字节都不动**。
`git diff --numstat` 里「改动行数 ≈ 文件行数」就是这个坑的信号。

判断行尾要用 `tr -dc '\r' < file | wc -c` 数 CR 字节数；
**`grep -c $'\r'` 在 Git Bash 下不可靠**（对 CRLF 文件会返回 0）。
